## 2. 设计决策

1. **用户画像写入方式（二选一）**：选择在「AI 自媒体系统」页下新建**「用户画像」子页面**，而不是写入 02_用户需求 库。理由：02_用户需求 是「逐条问题 + 证据链接 + 验证状态」的行式结构，而画像是多节点活文档（人群/兴趣/痛点/评分信号/负面清单），拆行会丢结构；画像性质是「用户提供的偏好」，不是逐条已验证需求。两者互补：后续采集到的具体用户问题仍写 02_用户需求。页面幂等创建（已存在则不改动）。
2. **画像同时进仓库配置**：`config/audience_profile.yaml`（profile_id=audience-zh-ai-creator-v1），评分代码经 `src/analysis/audience.py` 读取；修改信号词须升版本号（评分可追溯）。
3. **X 帖子输入接口**：`src/connectors/x_posts_source.py` 只读本地 JSON（不 import 任何网络库）；归一化 `normalize_x_post`：source_url **原样使用文件 url 字段**（任务硬约束）、证据等级 `self_reported`（作者自述未交叉核验）、互动数据进 extra。
4. **评分 v2**：`score_item` 接受众画像，「受众匹配」维度用画像高/中信号；命中负面信号（加密货币/撸毛/外国政治/行情等，任务书点名受众无关）→ 该维 0 分且总分降权；版本号携带 profile_id。启发式与 GLM 两引擎共用同一画像。
5. **GLM 两段式分析（控成本 + 防幻觉）**：本地预筛（画像信号 + 互动，负面直接出局，60 条）→ GLM 分批打分（0-10 + 理由）→ GLM 撰写 5-8 张中文选题卡。**硬校验在代码层**：引用帖子只允许来自输入素材池；链接一律取素材记录（即文件 url 原样），绝不用 LLM 生成的链接；字段缺失/引用非法的卡直接丢弃；<5 张标记 insufficient。
6. **Notion 写入量控制**：01_原始素材 只写被选题卡引用的素材（本轮 11 条，池 1063 条），避免写入上千条。03_选题决策 新增列（为什么适合/切入角度与钩子/国内可用性/引用帖子/综合评分）按「只增列」升级，旧库旧卡不受影响；01 source_type 下拉只增 `x_posts` 选项。
